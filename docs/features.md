# Features

How rho-ui behaves, in detail.

The composer's footer holds the session's settings: the permission mode (which tool calls run without asking) on the left, and on the right one button naming the model and reasoning, which opens the model list with search beside the reasoning levels and fast mode. New session opens the session right away, so these can be set before the first message; rho writes no file for a session until its first prompt, and the daemon discards an unused draft's session, so nothing is left behind. A setting changed while a turn runs applies when the turn ends.

A new session (Ctrl+N) starts in the project of the session on screen, else where the last new session started, else `DIR`. Above the draft's composer, "Start a session in" lists your projects, the most recently used first, with the draft's project checked; click one to move the draft there. rho-ui finds no projects on its own: you add them. Type an absolute or `~/` path in the search and choose Add, or choose Add project… for the desktop's folder chooser. A project is a folder, and for a git repository its main checkout, so adding a linked worktree or a subfolder adds the repository it belongs to, and sessions in its worktrees count toward its age. Hover a project and click × (or right-click it) to remove it from the list; its folder stays. rho-ui keeps the list in `$XDG_STATE_HOME/rho-ui/projects` (by default `~/.local/state/rho-ui/projects`). Ctrl+Shift+N starts a session with the keyboard in the list's search, which filters by name or path. In a git project, the button beside Add project… chooses where the session works: Local, the project's checkout, or New worktree, a git worktree that the rho daemon adds on a new `rho/…` branch from `HEAD`, so sessions in one repository don't write the same files. Choosing it makes nothing: the worktree is added when the first message goes, so switching back and forth leaves none behind. The draft's own session, which holds its settings, works in the checkout; the first message opens a session in the new worktree, gives it the draft's settings, and runs there. The daemon owns the worktree: it removes it once it is clean and merged, keeping the branch. `rho worktrees prune` removes those it can now. A session's directory is fixed once it opens, so moving the draft lets its session go and opens another in the new folder: the composer's text stays, and the settings start over from the new session's.

While a turn runs, Enter in the composer steers it: the text joins the turn's next model request. Until the model reads it, it waits above the composer, where you can take it back. A message the turn can't take (it waits on an approval, or the daemon had just begun a turn of its own) waits above the composer too, and goes as the next prompt once the turn ends.

Attach any file with the paperclip at the left of the composer's footer, by dropping it on the composer, or by pasting it (Ctrl+V) after copying it in a file manager; paste an image the same way. Each shows above the composer's text: an image as a tile, any other file as a card. Hover one to remove it, or press Backspace in the empty text box to remove the last. They go with the text as one message, text first, as rho's terminal UI sends them, and the transcript shows them above the message's text.

What goes depends on the file. A PNG, JPEG, GIF or WebP image goes as an image the model sees. A text file of up to 200,000 characters (what the terminal UI sends of a document it attaches) goes whole. Any other file, such as a PDF or a binary, or a longer text file, goes as its path, and the agent reads it with its own tools; its card says "Sent by path". Attachments in one message can come to 16 MiB once encoded, images counting a third more as base64: the daemon reads a message as one line of at most 16 MiB (`rho_protocol::MAX_LINE_BYTES`). A steer carries only text, so a message with attachments sent while a turn runs waits above the composer and goes as the next prompt once the turn ends, and so does any message sent after it.

Background work a session's turns started (processes, workflow runs, subagents) is listed above the composer while it runs, with a button to stop each one. A turn ends while its background work runs on: rho-ui opens sessions with `idle_wake: turn`, so when the work finishes the daemon starts a turn of its own that gives the model the result, and rho-ui shows that turn like any other. Work that ended stays listed with how it ended (its exit status, or stopped) until the model has its result.

The sidebar lists the daemon's saved sessions. Once a second it also asks the daemon which sessions have work under way, so a session that runs a turn or waits for an approval shows as working or waiting whichever client started it.

Settling and snoozing sessions is rho-ui's own idea; rho has no such state. Sessions started or continued in rho-ui list as active. Sessions from elsewhere, such as rho's terminal UI, start out settled, so the sidebar doesn't fill with old history; a session with work under way always lists as active, and snoozing, restoring, prompting, or steering one makes it rho-ui's. rho-ui keeps this in `$XDG_STATE_HOME/rho-ui/shelves` (by default `~/.local/state/rho-ui/shelves`). A settled session comes back when it has new activity in rho-ui, and a snoozed one when its time is up. Snoozed and Settled sit under the active sessions, folded; open one to see its sessions on one line each, and hover a session for its details.

Settings (Ctrl+, or the gear at the bottom of the sidebar) open in a dialog over the window and hold the theme, the UI scale, the UI font (default Noto Sans) and the code font (default JetBrainsMono Nerd Font), saved in `$XDG_CONFIG_HOME/rho-ui/settings`. The theme is dark by default, or light, or whichever the desktop uses (System), following it as it changes. System isn't the default because on Linux rho-ui starts before the desktop portal reports light or dark, so a dark desktop would see a light first frame, and a desktop with no portal would stay light. Both themes are rho-ui's own, in `crates/rho-ui/themes/rho-ui.json` (GPUI Kit's theme format), in place of Kit's stock ones.
